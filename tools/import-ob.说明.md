# 从 Ombre Brain 搬记忆过来

这个小脚本给**原来用 Ombre Brain（下面简称 OB）、现在想搬到这个记忆库的人**用。它把 OB 的记忆文件夹转成一个 JSON 文件，你再把这个文件导入进来。

它**只读** OB 的文件夹，一个字都不改、不删、不往里面写东西。它也不会自己往后端发任何东西，导入那一步由你自己来做。

## 它是照哪个版本写的

照 OB 原版（GitHub 上 P0luz/Ombre-Brain 的 main 分支，版本 **3.6.14**）的存储格式写的：一条记忆 = 一个 `.md` 文件，开头一段 YAML 头写着标签、时间这些，下面是正文。

如果你用的是别人二改过的 OB，可能会多几个字段。不要紧：**我们这边没有对应位置的字段，都会原样收进这条记忆的 `ob` 里，一个都不丢**，只是暂时不参与召回。

## 会怎么转

- 正文 → 记忆内容；标签 → 关键词；「为什么记得」→ 为什么记；引语 → 出处（一句一行）。
- 创建时间、最后一次被想起的时间、被想起的次数，都照搬。
- 钉住（pinned）、坐标（anchor）、保护（protected）的，都变成「固有」。
- 种类：
  - 普通记忆、永久记忆 → 记事
  - feel（感受）→ 经验
  - plan（计划）→ 约定：已完成的标「做到了」，放弃的标「不作数了」，其余「还作数」
  - I（自我认知）→ 看法
  - **信（letter）不转**，报告里会告诉你有几封
- OB 里的记忆都是 AI 自己记的，所以转过来一律算 TA 自己写的。
- 归档（archive 文件夹里）的会带上归档标记。OB 归档时会把原来的种类抹掉，脚本会按留下的线索尽量猜回来（像计划会留着状态），猜不出的算记事。
- 向量不转，导进来以后由这边重新算。
- 编号前面会加 `ob-`，免得跟这边已有的记忆撞号。同一个文件导两次，第二次会自动跳过，不会重复。

## 一步一步来

**第 0 步：找到 OB 的记忆文件夹。** 就是里面有 `dynamic`、`permanent`、`feel`、`plans`、`archive` 这些子文件夹的那一层，通常叫 `buckets`（Docker 部署的话，是你挂进容器 `/app/buckets` 的那个宿主机文件夹）。下面用「OB文件夹」代指它的路径。

**第 1 步：先只看数，不写文件。**

```
node tools/import-ob.mjs OB文件夹 --dry
```

它会打出一份报告：一共多少个文件、每种各多少条、归档几条、信几封没转、跳过了几个（以及为什么跳过）、最长的一条多少字、有几条超过 4000 字。**报告里只有数字，不会出现任何一条记忆的内容**，可以放心截图问人。

超过 4000 字的记忆太长了，召回的时候不好用，可以考虑之后拆开。

**第 2 步：真的转。**

```
node tools/import-ob.mjs OB文件夹 --out ob-import.json --ai 你的AI名字
```

- `--out`：转出来的文件放哪，不写就是当前文件夹下的 `ob-import.json`。不能放进 OB 文件夹里面。
- `--ai`：你在这边给 AI 起的名字（只能用字母、数字、`-`、`_`）。写了的话，报告最后会把导入地址直接写好给你。

如果记忆很多、文件超过后端一次能收的大小（1 MB），脚本会自动分成 `ob-import.1.json`、`ob-import.2.json`……报告里会列出来，按顺序一个一个导入就行。

**第 3 步：导入前先备份。** 把这边记忆库的数据文件夹整个复制一份放好，万一导进来不满意，可以换回去。

**第 4 步：导入。** 把转出来的文件发给 `POST /api/memory/你的AI名字/import`（网页上有导入入口的话，直接选这个文件）。导完可以去记忆页翻几条看看对不对。

## 一定要注意

- **转出来的 JSON 里是你的全部记忆**（AI 记下的关于你的所有事）。别传到网上、别发群里、别放进公开的网盘或仓库。导完不用了就删掉。脚本写出来的文件已经设成只有你自己能读。
- 读不了的文件（文件坏了、YAML 头没写完、正文是空的、不是 UTF-8 文字……）会跳过并计数，不会让整个转换中断。报告里按原因分好了，想救回来的话可以用 Obsidian 或文本编辑器打开看看。
- 有疑问先跑 `--dry`，它什么都不写。
