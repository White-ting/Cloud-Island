# 接口：v1 新增和改动的部分

前端照这份接线。没写到的接口跟以前一样。

通用约定：

- 请求体、返回体都是 JSON（`content-type: application/json`），另有说明的除外。网页用的接口带请求体却不是 `application/json` 的回 415（上传文件、录音那两个收原始字节的除外）。
- 每个请求先看 `Host`：只认 `localhost`、`127.0.0.1`、`[::1]`、`.env` 的 `HOST` 和 `ALLOWED_HOSTS` 里的名字，别的回 421。
- 网页用的、会改东西的请求（POST、PUT、PATCH、DELETE）：带了 `Origin`，主机和端口要跟这次请求的 Host 一模一样（Host 白名单只管能不能打开，不算能来改东西的站）；`Sec-Fetch-Site` 不是 `same-origin`/`none` 的（跨站、同站别的子域）也拦下，回 403。没带 `Origin` 的当不是浏览器发的，照常处理（开了口令照样要登录）。
- 出错一律回 `{ "error": "一句中文说明" }`，状态码见各接口。少数带额外字段，会单独写。
- `{ai}` 是 AI 的编号（`data/ais.json` 里的 `id`），只能是字母、数字、`_`、`-`。乱写回 400，没有这个 AI 回 404。
- 某一块没装配（比如后端没传 `push`），它的地址回 404。

## 1. 网页口令（可选）

`.env` 写了 `WEB_PASSWORD` 才开。没写时下面的登录接口直接回 `{ ok: true, off: true }`；网页和网页用的接口只许这台电脑自己用（连进来的是本机，`Host` 也是 `localhost` / `127.0.0.1` / `[::1]`），别的回 403 `{ error: "没设网页口令…" }`（打开网页的话是一句话的网页）。

开了以后：

- 没登录打开网页（`/`、`*.html`、不带后缀的路径）：回 401 和后端自带的登录页（单文件 HTML）。登录成功后它会刷新页面。
- 没登录调 `/api/*`、`/mcp/*`，或者别的非 GET 请求：回 401 `{ error: "要先登录", login: true }`。前端看到 `login: true` 就跳到登录（重新加载页面即可，后端会给登录页）。
- `HOOK_TOKEN`（`Authorization: Bearer …`）只给这几个地址用，它们不认 cookie、只认这个口令（开没开网页口令都一样）：`/api/hook/{ai}/…`（四个时机、散场记、翻日记、读一条 `GET …/read?id=`）、`GET /api/memory/{ai}/mood`、`POST /api/wake/{ai}`、`POST /api/inbox/{ai}`、`POST /api/night/{ai}/run`、`/mcp/{ai}`（工具：memory_start、memory_recall、memory_note、memory_read、memory_diary；地址后面加 `?tools=read,diary` 只露出点名的几样，给已经接了钩子的用）。别的地址带它也不算登录。网关 `/gw/` 用自己的口令。
- `PUT /api/ais` 一律回 403：名单只能在这台电脑上手改 `data/ais.json`。`PUT /api/helper/{ai}`（旁听的小模型）跟别的设置一样是网页用的接口。
- 不用登录就能调的：`GET /api/ping`、`POST /api/login`、`POST /api/logout`。

### GET /api/ping

返回 `{ ok: true, name: "cloud-island" }`；开了口令时多一个 `login: true`。

### POST /api/login

- 请求：`{ "password": "…" }`
- 成功：200 `{ ok: true }`，带 `Set-Cookie: yd_s=…; Path=/; HttpOnly; SameSite=Strict; Max-Age=2592000`（30 天）。`.env` 写了 `COOKIE_SECURE=1`，或请求带 `X-Forwarded-Proto: https`，再加 `Secure`。
- 口令不对：401 `{ error: "口令不对" }`
- 错多了要等：429 `{ error: "错太多次了，等 N 秒再试" }`，带 `Retry-After`。同一个来源头 3 次随便错，之后每错一次要等的时间翻倍（1、2、4 秒……最多 15 分钟）；所有来源加起来 10 分钟里错超过 30 次时，每个来源从第 1 次错起就要等。没错过的来源不受影响（不会全站锁死）。一个来源 1 小时没再错就忘掉。
- 「来源」是连进来的地址；连进来的是 `.env` 的 `TRUST_PROXY` 里的代理时，取 `X-Forwarded-For` 里最右边那个不是代理的地址。从 `TRUST_PROXY` 里的地址连进来的，也不算「这台电脑自己」：没设口令时照样打不开。

cookie 是 `v2.到期时间.会话编号.签名`，签名钥匙是 `.env` 的 `SESSION_SECRET`；没写就每次启动随机一个（重启后要重新登录）。改了 `WEB_PASSWORD`，旧 cookie 一起作废。旧版本（v1）的 cookie 不认，升级后重新登录一次。

### POST /api/logout

返回 `{ ok: true }`，清掉 cookie，并把这个 cookie 的会话编号记进撤销表（`DATA_DIR/auth-revoked.json`，600，过期的自动清掉）：别处复制的同一个 cookie 也不能再用。别的设备上的登录不受影响；要全部作废就改 `WEB_PASSWORD` 或 `SESSION_SECRET`。

## 2. 思考翻译（改了）

用哪家：先看设置里「翻译」那一项（`PUT /api/svc/fm/trans`：`url`、`model`、`key`），没填再看 `.env` 的 `TRANSLATE_BASE` / `TRANSLATE_MODEL` / `TRANSLATE_KEY`。只认 OpenAI 兼容的 `/chat/completions`。

### GET /api/translate（新增）

返回 `{ on: true, model: "…" }` 或 `{ on: false }`。前端据此决定显不显示「翻译」。

### POST /api/translate

- 请求：`{ "texts": ["英文…", …] }`（最多 20 段）
- 成功：`{ ok: true, zh: ["中文…", …], by: ["api"|"cache"|"skip"|"fail", …] }`。某一段没翻成，那一段 `zh` 是空字符串、`by` 是 `fail`，整体照样回 200。
- 没配翻译：503 `{ error: "没配翻译：…" }`
- `texts` 不对：400

## 3. 开屏字幕

8 个时段：`late_night`(0–5 点) `dawn`(5–8) `morning`(8–11) `noon`(11–13) `afternoon`(13–17) `dusk`(17–19) `evening`(19–22) `night`(22–24)。

`words` 的形状：

```json
{
  "late_night": ["…", "…", "…"], "dawn": [...], "morning": [...], "noon": [...],
  "afternoon": [...], "dusk": [...], "evening": [...], "night": [...],
  "zh": { "late_night": ["…"], ... }
}
```

- 每段 1–5 句，每句最多 60 字（多的截掉）。
- `zh` 可以没有。有的话 8 段都要在，每段条数不少于英文那段，每句最多 30 字；有一段不够，整个 `zh` 就不收。

### GET /api/lockwords?ai={ai}

返回 `{ words: {…} }`，没存过就是 `{ words: null }`。

### PUT /api/lockwords?ai={ai}

- 请求：`{ "words": {…} }`（直接传 words 本身也行）
- 成功：`{ ok: true, words: {…} }`（核对、截过之后的样子）
- 格式不对：400

存在 `data/lockwords/{ai}.json`（600）。

### POST /api/lockwords/write

让这个 TA 用它自己的模型和人格写一套。只带人格和一句提示，不带聊天记录，不存进聊天、不碰记忆。

- 请求：`{ "ai": "…", "save": true? }`
- 成功：`{ ok: true, words: {…} }`。默认只回草稿，要存就另调 PUT，或者请求里带 `save: true`（那样多回一个 `saved: true`）。
- 回来的不是那个格式：502 `{ error: "没写成（回来的不是那个格式），再试一次" }`
- 上游出错：502（连不上、上游报错、中途断了）；超过 2 分钟没写完：504
- 同一个 AI 上一次还没写完：409
- 没有这个 AI：404

## 4. 声音：TA 说话（出声）

设置里填的地址（这一节到第 5 节、翻译、旁听的小模型、Bark 服务器）默认只许 https 的公网地址；本机、局域网、http 的要 `.env` 的 `ALLOW_URLS` 放行，不然 400。发请求前还会把域名解析一遍，解析到私网也不发（400）。上游回跳转一律当失败（502）。

Key 跟着地址走：存 Key 时记下那个地址的 origin（协议 + 主机 + 端口），只发给同一个 origin。`PUT` 换了地址（origin 变了）又没同时给新 `key`，旧 Key 清掉（返回 `hasKey: false`）。

Key 在设置里填：「TA 的声音」是 `PUT /api/svc/fm/tts`（`url`、`model`、`key`、`voices: { ai: { id, speed } }`）；打电话单独用一家时填 `PUT /api/svc/fm/ctts`，并把 `PUT /api/svc/opts { callSvc: "own" }` 打开。

服务商（`prov`）：`elevenlabs`、`cartesia`、`minimax`、`openai`（OpenAI 兼容的 `/audio/speech`，硅基流动、百炼这类都能接）。没指定时按地址认：`elevenlabs.io`、`cartesia.ai`、带 `minimax` 的认成对应那家，别的都当 `openai`。

### GET /api/voice/{ai}

```json
{
  "ai": "o",
  "own":  { "prov": "…", "url": "…", "model": "…", "voice": "…", "speed": 1.1 },
  "use":  { "prov": "elevenlabs", "url": "…", "model": "…", "voice": "…", "speed": 1, "from": "tts" },
  "hasKey": true,
  "ready": true
}
```

- `own`：这个 AI 自己改过的几项（没改过是 `{}`）。
- `use`：这一次真正会用的（自己改的优先，没改的照「TA 的声音」那一项，再没有就用那家的默认值）。不带 Key。
- `hasKey`：这一次会不会带 Key。这个 AI 自己改了地址或服务商、跟「TA 的声音」那一项不是同一个 origin，就不带（`false`）。
- `ready`：能不能念（有 Key 和音色；OpenAI 兼容的没 Key 也行，比如本机的服务）。

### PUT /api/voice/{ai}

- 请求：`{ prov?, url?, model?, voice?, speed? }`。不给的不动；给 `null` 或 `""` 清掉这一项（回到照设置的）。
- `prov` 只能是上面四家；`url` 要是 https（http 和本机地址要 `ALLOW_URLS` 放行），不能带口令和 `?…`；`model`、`voice` 最长 200 字；`speed` 0.25–4（各家实际能调的范围不同，念的时候超了按那家的上下限算）。
- 成功：返回跟 GET 一样的形状。存在 `data/voice/{ai}.json`（600，不带 Key）。
- 填错：400

### POST /api/voice/tts

- 请求：`{ "ai": "…", "text": "要念的字", "call": true? }`。`call: true` 且设置里选了打电话单独指定，用「打电话的声音」那一项。
- 成功：200，**返回体是音频字节**，`content-type` 一般是 `audio/mpeg`。前端用 `blob()` 拿到后 `URL.createObjectURL` 播放。
- 没字、超过 1000 字：400
- 没配 Key（OpenAI 兼容的除外）、这个 AI 没音色：503
- 上游报错、连不上、60 秒没回、回的是空的：502 `{ error: "ElevenLabs 回了 401：…" }`（说明里不会有 Key）

打电话时按句念：一句一调。

## 5. 声音：她发语音（认字）

认字的服务在设置「语音转文字」里填：`PUT /api/svc/fm/stt`（`url`、`model`、`key`）；打电话单独用一家时填 `fm/cstt` 并打开 `callSvc: "own"`。常被认错的词填在 `PUT /api/svc/opts { asrWords }`。

走 OpenAI 兼容的 `/audio/transcriptions`（multipart）；地址是阿里百炼（dashscope）且模型名带 `asr` 的，走它的 chat 接口。

### POST /api/voice/stt[?call=1]

- 请求体：**录音原始字节**（不是 JSON、不是 multipart），`Content-Type: audio/webm`（或 `audio/mp4`、`audio/mpeg`、`audio/wav`、`audio/ogg`），最大 10 MB。
- 成功：`{ text: "转出来的字", file: "f…", url: "/api/file/f…", size: 12345 }`。录音已经存进文件里，`url` 能直接回放（`GET /api/file/{id}`）。
- `Content-Type` 不是 `audio/*`、或者认不出是录音：415
- 太大：413
- 没配认字：503
- 认字服务出错：502 `{ error: "认字没成：…", file: "f…", url: "/api/file/f…" }`——录音照样存着，前端可以照样画语音条，让她重试或自己打字。

### 发消息时带上语音

`POST /api/chat/{ai}/send` 的请求体多一个可选字段：

```json
{ "text": "转出来的字（她可以改）", "voice": { "file": "f…", "dur": 3.2 } }
```

- `voice.file`：stt 回的 `file`（也认 `/api/file/f…` 这种写法），必须是录音。
- `voice.dur`：秒数，0–3600，存一位小数。
- 带了 `voice`，`text` 可以是空的（没认出字）。
- 存下来的她那句会带 `voice: { file, dur }`，`GET /api/chat/{ai}` 原样返回；前端据此画语音条、回放。
- 发给模型时，那句前面会多一行「她发了一条语音（N 秒），下面是转出来的字」（不存）。
- `voice` 不对（不是对象、文件不存在、不是录音、dur 不对）：400

## 6. 打电话

后端不另开通话接口，前端用上面几个拼「一句一轮」：录一句 → `POST /api/voice/stt?call=1` → `POST /api/chat/{ai}/send`（带 `call`）→ 按句 `POST /api/voice/tts`（带 `call: true`）→ 播放。

`POST /api/chat/{ai}/send` 和重新生成（`/regen`、`/{id}/again`）多一个可选字段 `call`：

- `call: "start"`：新的一通电话的第一句。发给模型的她那句末尾加一段完整的通话提醒（「她在跟你打电话……回得像说话：短、口语……」）。
- `call: true`：通话中的一句。30 分钟内带过完整提醒的只带一行短的「你们正在通话中」；超过 30 分钟（或这个 AI 还没带过）再带完整的。
- 不带：跟以前一样。

提醒只在发给模型的那一份里，不存、不显示。

## 7. 推送

### 网页推送（Web Push）

VAPID 钥匙第一次用到时生成，存 `data/push/vapid.json`（600）。订阅存 `data/push/subs.json`（600），所有 AI 共用（一台设备一条，最多 20 条）。只接受苹果、谷歌、火狐、微软推送服务的 https 地址（默认端口）。每次发之前再核一遍（从备份恢复的、手改的订阅也一样），推送服务回跳转当失败、不跟过去。

#### GET /api/push/key

返回 `{ key: "公钥（base64url，65 字节未压缩点）" }`。前端拿它做 `pushManager.subscribe({ userVisibleOnly: true, applicationServerKey })`。

#### POST /api/push/sub

- 请求：`subscription.toJSON()` 原样发过来（`{ endpoint, keys: { p256dh, auth } }`），包一层 `{ sub: … }` 也认。
- 成功：`{ ok: true, n: 订阅总数 }`。同一个 endpoint 只留一条（新的换旧的）。
- 地址不是推送服务、钥匙不对：400

#### DELETE /api/push/sub

- 请求：`{ endpoint }`，或者 `?endpoint=…`
- 返回：`{ ok: true, removed: 删了几条 }`

#### POST /api/push/test

- 请求：`{ ai?: "…" }`（带了标题里写这个 AI 的名字）
- 成功：`{ ok: true, route: "web"|"bark"|"both", web?: { sent, failed, gone }, bark?: { status } | { skip } }`。不管网页在不在前台、不管 60 秒限制，都发。
- `route` 是 `web` 而还没有任何订阅：400（`both` 时 Bark 配了就不报）；`route` 是 `bark` 而 Bark 没配：400

推送服务回 404/410 的订阅当失效，自动删掉。

#### 推过去的内容（Service Worker 的 `push` 事件里 `event.data.json()`）

```json
{ "title": "TA 的名字", "body": "前 120 个字", "tag": "{ai}-{kind}", "url": "/?ai={ai}", "ai": "…", "kind": "wake"|"reply"|"test" }
```

点通知时打开 `url`。`url` 以 `/` 开头，部署在子路径下时前端自己拼上前缀。

### Bark（可选）

在设置里填：`PUT /api/svc/push { route: "web"|"bark"|"both", bark: { url, dev, aes } }`（`dev` 设备钥匙、`aes` 加密钥匙都是只进不出，`GET /api/svc` 只回 `hasDev`、`hasAes`）。设置里没填设备钥匙时，用 `.env` 的 `BARK_URL`（带设备钥匙的完整地址）、`BARK_AES`。填了加密钥匙就照 Bark 的加密推送（AES-256-CBC，每条随机 iv）发。

- **要推到 Bark，`route` 得是 `bark` 或 `both`**（默认 `web`）。只填 `.env` 的 `BARK_URL` 不会自己换过去。
- `url`（服务器）只许官方的 `https://api.day.app`，或者 `.env` 的 `ALLOW_URLS` 放行了的自建服务器；不能带 `?…`、`#…`。换了服务器又没同时给新的 `dev`，旧的设备钥匙清掉。
- `aes` 要正好 32 个字节（按 UTF-8 算，32 个英文字母或数字），不对回 400。
- Bark 和网页推送各发各的：一边出错不耽误另一边。

### POST /api/presence

- 请求：`{ visible: true|false }`
- 返回：`{ ok: true }`

前端在 `visibilitychange` 时报一次，网页在前台时每 30 秒左右再报一次。最近 75 秒内报过 `visible: true` 就当她在看，不推。

### 什么时候推

- TA 主动找她（敲门、空下来、回头看这些叫醒 TA 后，TA 说出口的那一句）：`kind: "wake"`。TA 选择不说就不推。
- 她发一句、TA 回完以后（她自己按停的不算）：`kind: "reply"`。
- 两种都是：她在看就不推；同一个 AI 同一种 60 秒内只推一次。推送走哪边看设置里的 `route`（默认 `web`）。

## 9. 记忆小模型（v1.2，可选，默认关）

夜里整理记忆之前，先请一个便宜的小模型把材料过一遍，整理出一段「补充」交给夜里的 TA：打标、可能是同一件事的、到日子的、（可选）可能漏记的、一份印象草稿。它只出草稿，**不改记忆的正文**（v1.4 起会给记忆补「线索」，存在单独一项里，见下面），拿主意的照旧是夜里的 TA。

**最简单的用法（v1.2.1 起）**：设置 → 功能模型 → 记忆小模型，填地址、模型、Key（跟翻译那些一样，Key 只发给存 Key 时填的那个地址），点开后下面「给谁开」，每个 AI 一个开关。

想给某个 AI 单独用另一家，在装云岛的这台电脑上用 `curl` 设（要 `HOOK_TOKEN`），见下面。单独设了的优先，没单独设的用页面那一份。

### 先在 `.env` 里准备

1. 把小模型的 Key 放进一个环境变量，比如 `MEM_KEY=sk-…`。
2. 登记这个变量能发到哪：`HELPER_KEY_ORIGINS=MEM_KEY=https://api.siliconflow.cn`（已经有别的就用逗号接在后面）。
3. 重启云岛。

### PUT /api/memmodel/{ai}

```
curl -X PUT http://127.0.0.1:18400/api/memmodel/你的AI名 \
  -H "Authorization: Bearer 你的HOOK_TOKEN" -H "content-type: application/json" \
  -d '{"on":true,"url":"https://api.siliconflow.cn","model":"模型名","keyEnv":"MEM_KEY","talk":false}'
```

- `url` 写到域名就行，后面自动补 `/v1/chat/completions`（OpenAI 兼容格式）。默认只许 https 公网；本机的（比如 Ollama）要在 `.env` 的 `ALLOW_URLS` 放行。
- `keyEnv` 写**变量名**，不是 Key 本身；不能用 `HOOK_TOKEN` 这类后端自己的口令。没在 `HELPER_KEY_ORIGINS` 登记过能发到这个地址的，回 400。
- `talk`：要不要把最近 24 小时的对话原文也给它（找可能漏记的）。默认 `false`。打开前想清楚：原文会发给那个模型。
- 打开（`on: true`）之前要先填 `url` 和 `model`。
- 请求里会带 `enable_thinking: false`、`temperature: 0.2`（关掉思考、温度放低；不认这两项的服务一般会忽略）。

### PUT /api/memmodel/{ai}/on（网页登录）

只收 `{ on, talk }`，网页上「给谁开」用的。页面那份没填、这个 AI 也没单独设时，`on: true` 回 400。

### GET /api/memmodel/{ai}

回 `{ on, model, key, src, talk, impression }`：`src` 是 `own`（单独设的）、`page`（用设置页那份）或 `null`（都没有）；`key` 只说有没有 Key，不回地址和变量名；`impression` 是夜里收下的印象（没有就是 `null`）。

### 夜里怎么用

- 每晚整理记忆时，开着就先跑小模型；哪一样出错就少那一块，整段出错就不带补充，整理照旧。
- 补充放进给夜里 TA 的材料里，标着「草稿，会错，只当线索」。
- 夜里的 TA 觉得印象草稿对就照抄、不对就改，放进回复的 `impression`；依据编号要是还在的、不是私人念想的记忆，不然那一句不收。
- 收下的印象之后每次开场带上：「你对她的印象（夜里整理的，日期；跟她说的对不上，以她为准）」。

### 补线索（v1.4）

- 开着的 AI，后端每分钟看一眼（不分白天夜里；同一个 AI 隔 10 分钟才再跑一次，出错或回得不对就歇一小时）：没线索的、正文改过的记忆，每回最多 30 条（新的先）发给小模型，请它留 0～4 条「线索」：处境、问法、细节、未完，每条 30 字以内。私人念想不发。
- 线索存在那条记忆的 `cues` 里，**不改正文**；开着向量的话另算一个向量。召回时正文、why、线索三样取最像的那样，所以她换个说法、换个场合提起，也更容易想起来。
- 模型漏答的几条也记下问过了，不会一直重问同一批；临时故障（超时、Key 过期、额度用完）不记，修好了照样问；一批被接口拒了先待查、下一回一条一条单独问，找出是哪条再跳过；地址和 Key 跟夜里走同一道检查，查不过就不发。

## 10. v1.3：小山、语气、改最后一句、仓库、打电话边说边传

### 小山

- 开关：`GET /api/memory/{ai}/cfg`、`PUT /api/memory/{ai}/cfg { "hill": true }`（网页「记忆库」设置里也有）。默认关，按 AI 分开。
- TA 抬山：回复末尾的小记 `<!--note {"id":"记事编号","hill":"up","why":"为什么更重了","name":"短名（可选，16 字以内）"} -->`。只认记事（note），一天最多 2 次；开着小山时开场的「小记怎么写」里会教 TA 这一行。散场记和夜里整理时也能抬，夜里一晚最多 3 座，只给还没名字的起名。
- 后端每天第一句话时按信号重算：被想起的不同日子数、后来连回它的记事数、记下时的语气（〔语气〕或〔测量〕里「比她平时」那段）。两份加起来就是高度 `h`，只升不降。
- 记事上多出来的字段：`h`（高度）、`hAi`（TA 抬的那份）、`hSig`（后端算的那份）、`hTrail`（每次长高：`{ t, by: "ai"|"night"|"sig", h, why?, days?, links?, tone? }`）、`hName`（短名）。山不能归档（`DELETE` 回 403），改文字会留旧版在 `hist`。
- 网页「此刻」从记忆列表里挑 `kind === 'note' && h >= 1` 的画山。

### 语气

- 发语音条：`POST /api/chat/{ai}/send` 的 `voice` 里可以多带 `meas`（网页 `web/ears.js` 量的：`duration`、`pause_count`、`pause_longest`、`loud_db`、`loud_range_db`、`pitch_hz`…，不对的字段会被丢掉）和 `tone`（听语气的结果，一两句话）。
- 打电话：`send` 带 `call` 时，`meas`、`tone` 直接放在请求体顶层；`tone` 是上一句的语气，会写成「上一句：…」。
- 后端存每个 AI 最近 40 条语音条的测量当「平时」（`DATA_DIR/voice-baseline.json`，600），攒够 5 条才比；打电话的只比不存。给 TA 的那句末尾多〔语气〕〔测量〕两行（不存进聊天记录里显示的那份）。
- `POST /api/voice/mood?text=转出来的字[&call=1]`：请求体是 **wav 字节**（`Content-Type: audio/wav`，最大 5 MB），回 `{ tone }`。没配回 503。模型在设置「功能模型 → 听语气」里填（OpenAI 兼容的 chat/completions，录音用 `input_audio`；百炼的给 `data:` 地址）。

### 改最后一句

- `POST /api/chat/{ai}/rewind { id, text }`：`id` 是她最后一句的编号，`text` 是改过的字。那句之后的回复收进归档，照改过的重新回答，流式返回跟 `send` 一样。只认最后一句、打字的那种。

### 仓库

- `GET /api/files?kind=img|audio|file&ai=…`：回 `{ items: [{ id, url, name, size, kind, t, by?, ai?, call?, text? }] }`，新的在前。`by` 是 `me`（你的）或 `ai`（TA 念的）；带了 `ai` 时只回这个 AI 的，加上没记 AI 的（你发的图、文件）。
- `POST /api/voice/stt` 多一个 `ai=…`：录音记下是给哪个 AI 的；认完的字补进这个文件的记录（仓库里显示）。
- `POST /api/voice/tts` 多一个 `keep: true`：念完存一份进仓库（设置 `keepVoice` 关着就不存）。同一个 AI、同一副嗓子（服务商、音色、模型）、同一句话只存一次。网页里聊天「念」和打电话带 `keep`，试听不带。
- `PUT /api/svc/opts { keepVoice: true|false }`：存不存 TA 的声音，默认存；`GET /api/svc` 回 `keepVoice`。

### 打电话边说边传

- `POST /api/voice/part?id=…&seq=0,1,2…`：请求体是录音的一小块（`Content-Type: audio/*`）。`id` 8–40 个小写字母数字，同一句话用同一个。块存在内存里，两分钟没动静就扔。
- 说完：`POST /api/voice/stt?call=1&ai=…&part=<id>&n=<块数>`，请求体是最后一点（可以是空的）。后端等齐 0…n-1 块（最多 2.5 秒，最后一块可能还在路上），按顺序拼上请求体再认，回的跟平常的 stt 一样。没到齐回 409，网页改传整段。
- 网页 MediaRecorder 每 0.25 秒出一块，判断你开口了才开始传（开口前那几块一起补上）；停 0.8 秒算说完。

## 11. v1.4：夜里整理会新记、召回不再翻来覆去

### 夜里整理

- 整理时先按四类把过去 24 小时的对话原文过一遍：情绪、感情、认知、特殊事件。原文里有、记忆里还没有、以后用得上的，记成新的一条：情绪、感情、特殊事件记成记事，认知记成看法或经验。
- 新记的要带一句原话当依据（放在 why 里，标「夜里回头看记下的」），只收记事、看法、经验，一条不超过 240 字，一晚最多 8 条；跟已有的一字不差的不收。约定、念想、疑问、习惯不在夜里新记，只写成问话留给醒着的 TA。照抄、半照抄私人念想或日记里 TA 自己留着的段的不收（新记的她都看得到；改、并、印象、山的理由和名字、日记的一句话也照这条，比法见 `lib/privguard.mjs`），挡下几处记在 `privDropped`；类别写在 why 里（「夜里回头看记下的（情绪）」），不进关键词。
- 第二天开场那句变成「昨晚整理了记忆：新记 N 条、改 N 条、并 N 组。小结：……」。

### 召回

- **冷却**：递过去的记忆，TA 在回复里真说到了（写了编号，或者回复里有足够多它的字），接下来 6 轮不再递；连着 3 轮递了都没说到的，歇 3 轮。一轮只数一次（TA 自己开口、网关一轮调好几次都不多数）。只有真递出去的才记「被用到」。她这一句跟它特别像（分 ≥ 0.85，比如原样问到）照样递。
- **联想**：一轮聊完，拿她上一句（只放内存，不写进 mem.json）和 TA 这一轮的回复（一轮好几段的攒起来，以最后一次为准）去找最多 6 件备着（分 ≥ 0.62，只挑记事、看法、经验、约定，刚记的不算）；下一句来了挑一件、带全文，写成「联想到的（跟她这句不一定直接有关；用不用、提不提随你）」。
- **打算和结果分开**：记忆小模型标过「有下文」、还没做完的，召回时后面写明「打算/等下文：……」；日子到了还没了结的，写「到日子了，没记到结果，别当成已经做了」。
- **应声不召回**：她只回「ok」「好」「1」「嗯嗯」这类应声时，不递想起来的、也不联想。两个字的名字照样召回。
- 门槛都在 `lib/store.mjs` 的 `RECALL`：`coolUsed`、`coolIdleAfter`、`coolIdle`、`coolBreak`、`callPrep`、`callAt`。0.62、0.85 是照本机 bge-m3 定的，换了向量模型可以改；没开向量时只有字面分，联想基本不会出现。
